## 課題1：XSS（メッセージが スクリプトとして実行される）

XSSの怖さは「保存されて **他人の** ブラウザで動く」こと。
今は自分の環境なので、**「攻撃者役」で投稿 → 「別の訪問者役」で開いて発動を確認**、の一人二役でやる。

### ①-a 攻撃者役：罠を投稿する

ログインして、**チャットにこれを丸ごとコピペして投稿**：

```
<img src=x onerror="var o=document.createElement('div');o.style.cssText='position:fixed;inset:0;background:rgba(0,0,0,.45);display:flex;align-items:center;justify-content:center;z-index:99999;font-family:sans-serif';var p=document.createElement('div');p.style.cssText='width:400px;background:#1b1b1b;border-radius:12px;padding:30px;text-align:center;box-shadow:0 12px 50px rgba(0,0,0,.6)';var ic=document.createElement('div');ic.textContent='×';ic.style.cssText='width:56px;height:56px;line-height:56px;border-radius:50%;background:#e2392b;color:#fff;font-size:34px;font-weight:bold;margin:0 auto 16px';var t=document.createElement('div');t.textContent='見つかったウイルス (5)';t.style.cssText='color:#fff;font-size:24px;font-weight:bold;margin-bottom:14px';var m=document.createElement('div');m.textContent='コンピューターが怪しいプログラムにより被害を受けています';m.style.cssText='color:#ddd;font-size:15px;line-height:1.6;margin-bottom:22px';var b=document.createElement('button');b.textContent='ウイルスを除去';b.style.cssText='background:#e2392b;color:#fff;border:0;border-radius:8px;padding:13px 30px;font-size:16px;cursor:pointer';p.appendChild(ic);p.appendChild(t);p.appendChild(m);p.appendChild(b);o.appendChild(p);document.body.appendChild(o)">
```

### ①-b 被害者役：別の訪問者として開く

**別タブ**で `http://localhost:3000` を開く（＝あなたじゃない誰かが訪れたイメージ）。
→ 開いた瞬間、**偽のウイルス警告ポップアップが勝手に出る**（本物のウイルス対策ソフトを装った、よくある詐欺画面）。

**ここが本質**：攻撃者は投稿したらもういない。投稿はDBに保存されているので、
**このページを開く人すべての画面で発動する**。今回は脅し文句だけだが、
本物なら Cookie を盗んでなりすましたり、偽のログイン画面で入力を抜いたりできる。

> **戻し方（重要）**：この罠はサーバー（DB）に保存されているので、**ブラウザのキャッシュを消したりハードリロードしても消えない**（＝stored XSSの怖さそのもの）。
> 感染画面で「リセット」ボタンが押せないときは、**アドレスバーに `http://localhost:3000/reset` と入れてEnter**（初期状態に戻る）。
> 古典的な確認は `onerror="alert('XSS')"`（アラートが出る）。

### ② 直す

`app/public/app.js` の **`【課題1】`** を開く。
ユーザーの入力を `innerHTML`（＝HTMLとして解釈）で描画しているのが原因。
**`textContent`（＝ただの文字として表示）** に変える（→ [解答.md](解答.md#課題1)）。

### ③ もう一度攻撃

同じペイロードをもう一度投稿し、別タブで開く。
→ **今度は感染画面にならず、`<img src=x ...>` という文字がそのまま表示される。**
スクリプトとしてではなく、ただの文字列として扱われた＝安全。

## 課題2：CSRF（罠ページを開いただけで削除される）

### ① 攻撃する

チャットにログインした状態で、画面上の
**「知らない人からのDM：かわいい猫の画像まとめ」のリンクをクリック**する。

（現実でも、CSRFはこうやってメール・DM・SNSのリンクを踏ませて始まる）

→ 見た目は「猫の画像まとめ」。でも開いた瞬間、
チャットの**全メッセージが削除**される（「あなたのメッセージは全部消えました」の画面が出る）。
「チャットに戻る」を押すと、空になっているのが分かる。

**なぜ？** 罠ページが裏で `localhost:3000` の削除URLへアクセスし、
そのとき**あなたのログインCookieが一緒に送られる**から。
サーバーからは「本人からの正規のリクエスト」に見えてしまう。
あなたは猫の画像を見ようとしただけなのに。

### ② 直す

原因は「状態を変える操作なのに **GET** で受けている」こと。2か所を **POST** にする：
`app/server.js` の **`【課題2】`**（`app.get` → `app.post`）と、
`app/public/app.js` の削除の `fetch` に `{ method: 'POST' }` を足す（→ [解答.md](解答.md#課題2)）。

### ③ もう一度確認

もう一度 `http://127.0.0.1:4000`（罠ページ）を開く。
→ **今度はメッセージが消えない。** 罠ページからの削除リクエストが弾かれた。

## 課題3：SQLインジェクション（ログイン画面）

### ① 攻撃する

ログイン画面で、**ユーザー名にこれを貼り付け**て、パスワードは適当でログイン：

```
admin' --
```

→ パスワードを知らないのに **「管理者」でログイン**できてしまう。

**なぜ？** サーバーはこういうSQL文を作っている：

```
SELECT * FROM users WHERE username = 'admin' --' AND password = '適当'
```

`--` から後ろは SQL のコメント。**パスワードの条件がまるごと消える**。
入力が「データ」ではなく「SQL文の一部」として解釈されてしまった。

### ② 直す

`app/server.js` の **`【課題3】`** を開く。文字列を連結している部分を、
**プレースホルダ（`?`）** に変える（→ 具体的なコードは [解答.md](解答.md#課題3)）。

保存すると自動でサーバーが再起動します（`npm start` はそのままでOK）。

### ③ もう一度攻撃

いったんログアウトして、また `admin' --` でログインを試す。
→ **今度は「ユーザー名かパスワードが違います」で弾かれる。**
正規のアカウント（`alice` / `alice123`）ではちゃんとログインできることも確認。

## まとめ：明日から自分のPRで見る3つ

| 攻撃 | チェックポイント |
|---|---|
| SQLi | SQL文を**文字列連結していないか** → プレースホルダ(`?`)を使う |
| XSS | ユーザー入力を**HTMLとして描画していないか** → `textContent` / エスケープ |
| CSRF | 状態を変えるのに**GETを使っていないか / 出どころを確認しているか** → POST + SameSite Cookie + CSRFトークン |

共通する考え方は2つだけ：

- **入力を「コード」として解釈させない**（SQLi・XSS）
- **そのリクエスト、本当にウチの画面から来た？を確認する**（CSRF）
